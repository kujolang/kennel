Getting started

Install once.
Use everywhere.

{{notice}}

Requires macOS or Linux and Kujo 1.4.0 or newer. Kennel does not require Python. No administrator access is needed. The installer adds ~/.kennel/bin to Bash, Zsh and POSIX shell profiles.

Install the Kujo runtime

The Kujo installation guide lists the current runtime, supported platforms, native archives, checksums, and the npm package @kujolang/kujo-runtime. The Kennel bootstrap supports macOS and Linux and requires Kujo 1.4.0 or newer. Install Kennel and update project packages separately.

Wave C effect assurance and Wave D participant interoperability remain experimental companion contracts. Participant SDK packages are private/unpublished; runtime availability does not publish or stabilize them.

Install Kennel

curl -fsSLO https://kennel.kujolang.ai/install.sh
sh install.sh
. "$HOME/.kennel/env"
kennel --version

Inspect install.sh and install.kujo before running them. The shell entrypoint launches Kujo; Kujo downloads, verifies and installs the release. Use sh install.sh --no-modify-path to configure PATH yourself. Fish users can run fish_add_path ~/.kennel/bin.

Global tools

kennel tool install shipcheck
shipcheck --help
kennel tool list
kennel tool update shipcheck
kennel tool remove shipcheck

Tools run from your current directory. Installation records exact versions and checksums and protects existing commands. Exact versions stay pinned; use kennel tool install shipcheck@1.0.0 to select one.

Project dependencies

kennel init --name my-project
kennel add ability
kennel install

Project dependencies stay inside the project and do not add global commands.

Keep Kennel updated

kennel self update

A failed update preserves your current client and tools. Pin a client with kennel self update --version VERSION.

Publish a tool

Enrolled official projects publish through actual GitHub Releases. Keep kennel.toml and release versions aligned; the registry checks for releases every 15 minutes. Declare commands:

[bin]
my-tool = "main.kujo"

Entries may be .kujo files or executable sh, Bash or Python scripts with supported shebangs. A particular third-party script can require its own interpreter; Kennel itself does not. Historical packages can use [kujo].entry. Libraries use kennel add.

Agent City uses its own installer

Agent City is a local workspace for agent tasks, review, and replay in a pixel-art city. Its installer supplies the application and pinned Kujo dependencies for macOS and Linux.

Agent City is not a Kennel package. Use its versioned installer rather than kennel add agent-city or kennel tool install agent-city:

curl --proto '=https' --tlsv1.2 -fsSL https://github.com/kujolang/agent-city/releases/download/v0.2.0/install.sh | sh

Configure your own Ollama or Codex connection after installation. Workcell execution and VideoOps rendering need a compatible container engine and explicit permission. See the Agent City setup guide and 0.2.0 release.

Build and verify with Software Factory

Software Factory 0.2.0 helps you turn a brief or issue into a locally tested candidate. Use its pinned agent and skill catalog to plan work, run independent checks in rootless Workcell, and hand reviewers an evidence bundle they can verify offline.

Install the standalone GitHub release with Git and npm. It uses Node 26.12.1 or later 26.x and requires a configured rootless Docker engine with seccomp for live checks.

git clone --branch 0.2.0 https://github.com/kujolang/software-factory.git
cd software-factory
npm ci
npm run setup

Follow the versioned setup guide. Kennel continues to install enrolled Kujo tools and libraries. Software Factory has its own dependency pins, setup, and GitHub release.
