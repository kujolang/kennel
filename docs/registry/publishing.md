# Official release publisher

Development stays on GitHub. Publish a real GitHub Release; the small `.github/workflows/kennel-release.yml` caller invokes the central workflow. The builder never executes package code/hooks and reads exact tracked Git blobs at the tag commit. It applies existing `[kujo].sources/includes/excludes`, mandatory secret/cache/output exclusions and a portable path policy. Files sort lexically; USTAR uid/gid/mtime and gzip mtime are zero; modes normalize to 0644/0755. The same input plus publishing context produces identical metadata; reruns preserve the first immutable provenance statement.

GitHub policy disables deploy keys. Release callers build and validate package artifacts with read-only credentials; registry-owned reconciliation/backfill independently consumes published Release records and uses its own GITHUB_TOKEN to write. This avoids cross-repository credentials. Publication can wait for the next scheduled reconciliation (nominally 15 minutes; GitHub may delay scheduled runs). The explicit official policy checks repository name and immutable ID, enabled flag, owner and package name. Push races fail closed; scheduled release reconciliation repairs missed events. A registry commit contains every new blob/version manifest plus regenerated package/global indexes and human pages. Cloudflare Pages Git integration exposes that snapshot atomically.

Backfill: dispatch `kujolang/kennel-registry` workflow `releases.yml`, optionally selecting an enrolled package and existing numeric Release ID. No new test release is necessary. The workflow verifies production discovery/archive digests after publication. Manual recovery restores complete verified version artifacts from Git history; do not rebuild a published version under the same identifier.

Historical Changebucket v1.0.0 uses ChangeBudget source at commit `bea11cf488aa916b68cab5e178378eeb10c0bb82`. A policy entry pinned to this commit permits deriving `kennel.toml` from its original `kujo.toml`, preserving version and recording original identity/generated manifest digest in provenance. All released code bytes remain unchanged; no license is invented.

No SBOM is fabricated. The existing release SBOM/attestation workflow remains available; its attestation applies to the SBOM, not these archives. Future archive attestations should be verified independently and exposed through additive metadata.
